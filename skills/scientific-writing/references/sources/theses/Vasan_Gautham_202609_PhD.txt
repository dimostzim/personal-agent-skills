Abstract

A robot that learns from its own runtime experience can improve its behavior over

its operational lifetime and adapt to conditions that were never anticipated. The
prevailing practice in robot learning provides no such ability: practitioners train
a control policy before deployment, from human-provided data or from simulated

interaction, and hold it fixed afterward. When performance degrades after deploy-
ment, a human engineer may need to diagnose the failure, collect more data or
refine the simulator, and retrain and redeploy the policy. Reinforcement learning

(RL) from ongoing interaction could reduce reliance on humans for data collection,
retraining, and redeployment.
   Real-time reinforcement learning names the setting in which an agent senses,

acts, and learns from ongoing interaction as wall-clock time advances for both the
agent and the environment. Real-time RL on physical robots imposes three practical
demands: (a) learning must operate within the robot’s limited computational and

memory resources; (b) learning must reach competent performance reliably within
a practical wall-clock budget; (c) learning must use rewards that are computable
from the robot’s own sensing and simple to specify across tasks. I present three

complementary contributions that address the three demands.
   The first contribution, the Remote-Local Distributed (ReLoD) framework, sup-
plements the robot’s limited computational resources with a remote workstation.

The framework distributes action computation and learning updates between the
two computers. Experiments on vision-based tasks showed that the performance

                                        ii
of an agent using Soft Actor-Critic, a widely used batch RL algorithm that learns

from stored transitions, degraded under limited onboard computation. A robot us-
ing ReLoD recovered performance by drawing on remote computation. Across
repeated runs, competent policies were learned from scratch within a few hours.

   The second contribution is an empirical study of the minimum-time task speci-
fication, which assigns a reward of −1 at each timestep and terminates the episode
when the goal is reached. Given matched interaction budgets, final policies learned

under the minimum-time specification matched or outperformed those learned un-
der guiding reward specifications, which reward progress toward the goal. Using
the minimum-time specification, four physical robots learned goal-reaching policies

from raw-pixel observations within hours and without external instrumentation.
   The third contribution is Action Value Gradient (AVG), a computationally cheap
streaming RL algorithm that learns with neural networks. An agent using AVG up-

dates its parameters once from each transition (an observation, action, reward, and
next observation) and stores no transitions for reuse. On simulated tasks, agents us-
ing AVG outperformed agents using existing streaming RL methods, often achiev-

ing final performance comparable to batch RL methods. On physical-robot tasks,
agents using AVG learned competent policies within hours on an edge device.
   The three contributions address the three demands in complementary ways.

ReLoD and AVG meet the computational resource demand from opposite direc-
tions: ReLoD supplements a robot’s onboard computer with remote computation
when feasible, and AVG is computationally cheap, enabling on-device learning.

The minimum-time specification reduces specifying a goal-reaching task to one
requirement, detecting the goal from onboard sensing. Across the contributions,
physical robots learned competent behavior from scratch within hours. Together,

the contributions advance real-time reinforcement learning on physical robots to-
ward the longer-term goal of continual adaptation and long-term autonomy.

Introduction

Learning from experience is essential for an agent operating in a large, dynamic
world. Consider a squirrel in the Canadian Rockies: in summer, greenery flour-
ishes and food is abundant, whereas in winter, trees wither and resources become
scarce. To survive, the squirrel must adapt continuously, adjusting foraging behav-
ior across seasons, detecting predators, navigating shifting terrain, and remember-
ing the locations of hidden food caches. A robot navigating a warehouse faces the
same challenge: inventory shifts, routes change, and new obstacles appear. Like the
squirrel, the robot can be modeled as an agent that must make decisions over time
in an unpredictably changing environment. Without the ability to adapt, a robot
must be reprogrammed for every new situation, requiring costly human effort that
scales poorly. A robot that learns continuously and autonomously could adapt to a
non-stationary world without costly human intervention.
   In this dissertation, I develop a computational framework and an algorithm,
each instantiated in complete robotic systems that learn on the fly through interac-
tion with the world, and I investigate whether simple task specifications suffice for
goal-reaching problems. I use the word system to mean an integrated collection of
hardware and software components that together produce behavior. To learn from


                                         1
ongoing interaction with the world, a robot must repeatedly sense its current situa-
tion, take actions, and update its behavior from the feedback that follows. The real
world does not pause for the robot’s computation; other agents move, objects shift,
and conditions change. Real-time learning names the setting in which an agent
senses, acts, and learns from ongoing interaction as wall-clock time advances for
both the agent and the environment.
   Reinforcement learning (RL) is a natural approach to learning from ongoing
interaction: rather than being told which actions to take, an agent discovers which
actions yield the most reward through trial-and-error interaction with its environ-
ment (Sutton & Barto 2018). An RL agent learns a policy that maps situations to
actions to maximize cumulative reward over time. A practitioner need not specify
behavior directly. Instead, the practitioner specifies the task through the reward sig-
nal, and the agent discovers the behavior. The choice of task specification shapes
both what the agent learns and how quickly it learns. RL offers a powerful way
to acquire sophisticated robotic skills that are otherwise difficult to hand-engineer
(Kober et al. 2013). Applying RL in a real-time setting, however, is not straightfor-
ward: standard RL methods do not immediately translate to the practical demands
of real-time operation.
   Real-time reinforcement learning on physical robots imposes three practical de-
mands. First, learning must operate within the robot’s limited computational and
memory resources, which are also used for sensing, acting, and other processes.
The robot must compute each action within its action cycle time, the fixed interval
between successive action selections. The requirement is soft: a late action does not
halt the robot, but control degrades with the delay. Learning updates need not finish
within a single action cycle, but slower updates can delay adaptation. Learning must
therefore make economical use of the limited resources while still adapting quickly.
Second, a robot must learn reliably in limited wall-clock time. Learning on phys-

                                          2
ical robots is costly: experience consumes equipment time and energy, hardware
wears down with use, and poor exploration risks damage. Therefore, both learning
time and run-to-run consistency matter. Across repeated runs with fixed hyperpa-
rameters and the same experimental protocol, learning should reach a competent
level of performance within a practical wall-clock budget. Third, learning should
use rewards that the robot can compute from its own sensing and that are simple
to specify across tasks. A reward signal that depends on resources absent where
and when the robot operates, such as external instrumentation or sustained human
feedback, cannot support learning during deployment (Hafner et al. 2021, Ibarz et
al. 2021). Rewards computed from onboard sensing alone free the robot from that
dependence. A long-lived robot would also be expected to solve many tasks over
its lifetime, and engineering a reward function for every task by hand scales poorly.
Rewards that are simple to specify limit the per-task effort. Real-time learning
must therefore meet the robot’s action-cycle, computation, and memory constraints,
reach competent performance reliably within a practical wall-clock budget, and use
rewards computable onboard and simple to specify across tasks.
   In streaming reinforcement learning, an agent learns from a stream of experi-
ence by using each arriving transition—an observation, action, reward, and next
observation—for one learning update and then discarding it rather than retaining it
for later reuse. This regime requires no memory for experience replay, and each
update processes one transition rather than a batch, making it well suited to real-
time RL on resource-constrained robots. Early demonstrations of real-time RL on
physical robots used streaming updates (Mahadevan & Connell 1991, Benbrahim
et al. 1992, Gullapalli et al. 1994, Gaskett et al. 2000). Chapter 3 documents the
later adoption of replay buffers and batch updates alongside increases in available
computational resources (Hafner & Riedmiller 2003, Riedmiller 2005b, Lange et
al. 2012, Haarnoja et al. 2019).

                                         3
   Replay and batch updates introduce a resource–performance tradeoff. Reusing
transitions can improve sample efficiency, and averaging updates over batches can
reduce the variance of individual updates, important benefits when physical-robot
experience is costly (Gu et al. 2017, Riedmiller et al. 2022). A fixed-capacity
replay buffer has bounded memory, but its experience-storage requirement scales
with the chosen capacity. A batch update processes multiple transitions, and its
arithmetic cost therefore scales with batch size, although its wall-clock duration
also depends on the model, hardware, parallelism, and update schedule (Yuan &
Mahmood 2022, Smith et al. 2023). Whether replay and batch updates reduce
total wall-clock learning time therefore depends on whether their gains in sample
efficiency outweigh their additional computation.
   Two widely used approaches in robot learning—learning from demonstrations
and simulation-to-reality transfer—often use train-then-deploy workflows rather
than learning in real time. In these workflows, practitioners train a policy before
deployment and hold it fixed during deployment. In learning from demonstrations,
practitioners train policies from human-provided trajectories, including teleoper-
ated robot demonstrations and video demonstrations (Fu et al. 2020, Chi et al.
2024). In simulation-to-reality transfer (sim-to-real), practitioners train policies us-
ing large amounts of simulated interaction before transferring them to a physical
robot (Akkaya et al. 2019, Miki et al. 2022, Degrave et al. 2022).
   When training is separate from deployment, learning updates need not run under
the constraints of real-time operation. Training need not meet the robot’s action-
cycle deadline and can use computational resources unavailable to the deployed
robot. During deployment, policy inference must still fit within the action cycle,
but the robot need not allocate compute or memory to learning updates or experi-
ence replay. Human demonstrations reduce the need for autonomous trial and error
on physical hardware. Sim-to-real shifts experience collection to simulation, where

                                           4
interaction is inexpensive, exploration poses no risk to hardware, and privileged
information unavailable during deployment can be used to compute rewards. The
separation is also attractive because reliable real-time learning remains difficult.
Successful real-time RL on physical robots often depends on careful task setup,
well-tuned hyperparameters, and substantial computation during operation (Mah-
mood et al. 2018a, Mahmood et al. 2018b, Haarnoja et al. 2019). Unsuitable
task setups, poorly chosen hyperparameters, or insufficient computation can result
in slow or failed learning (Dulac-Arnold et al. 2021, Ibarz et al. 2021).
   Separating training from deployment limits adaptation after deployment. Two-
stage workflows are well suited to tasks and environments known in advance, but
they are less suited to conditions that change in ways not anticipated during train-
ing. Before deployment, demonstrations must be performed, collected, and curated
(Brohan et al. 2022, Amin et al. 2025), or simulators must be designed, calibrated,
and refined (Akkaya et al. 2019, Torne et al. 2024). After deployment, degraded
performance must be detected and corrected. An automated monitor can detect it,
but correction currently falls to a human engineer. The engineer diagnoses the prob-
lem, collects additional demonstrations or refines the simulator, retrains the policy,
and deploys the new policy (Amin et al. 2025, Luo et al. 2025); each unanticipated
change repeats the cycle. The required time and expertise grow with the number of
robots and the length of their operation.
   For robots operating over long periods in changing environments, autonomy
requires more than a policy that performs well at initial deployment. A policy
whose parameters remain fixed may generalize to unfamiliar conditions, but it can-
not update its behavior from experience collected after deployment. Real-time RL
provides a mechanism for updating behavior after deployment and could reduce
reliance on humans for data collection, retraining, and redeployment. Robots that
update their behavior from post-deployment experience could therefore operate au-

                                            5
tonomously for longer with less human intervention.
   Learning reliably from runtime experience is necessary, but not sufficient, for
continual adaptation. This dissertation studies that requirement by examining how
physical robots can learn control policies during operation while meeting action-
cycle, computation, and memory constraints, reaching competent performance re-
liably within practical wall-clock budgets, and limiting task-specific reward engi-
neering. The empirical studies evaluate learning within bounded experimental runs,
not adaptation across a sequence of environmental or task changes. Together, my
contributions advance real-time robot learning toward the longer-term goal of con-
tinual adaptation and autonomy.



1.1     Research Objective and Contributions

  My objective in this work is to advance real-time reinforcement learning on
  physical robots by addressing three practical demands: (a) selecting each ac-
  tion within its deadline and learning within the computation and memory avail-
  able to the robot; (b) reaching competent performance reliably within a practi-
  cal wall-clock budget; and (c) using rewards that are computable onboard and
  simple to specify across tasks.



   I pursue this objective through three complementary contributions to real-time
RL: a distributed computing framework, an empirical study of a simple task speci-
fication for goal reaching, and a streaming reinforcement learning algorithm.


   1. The Remote-Local Distributed (ReLoD) computational framework for
      real-time RL. I develop ReLoD, a framework that supplements the robot’s
      onboard computational resources with a remote workstation. The framework
                                        6
  distributes action computation and learning updates between the two comput-
  ers. I first show that the performance of an agent using Soft Actor-Critic, a
  widely used RL algorithm, degrades as onboard computational resources are
  reduced. Under the same onboard limits, a robot using ReLoD recovers per-
  formance by drawing on remote computational resources during operation.
  Across repeated physical-robot runs, robots using ReLoD learn vision-based
  control policies from scratch within a few hours. ReLoD addresses the com-
  putational part of the first demand, while the repeated-run results provide
  evidence of reliable learning within a practical wall-clock budget.

2. An empirical study of the minimum-time task specification for goal
  reaching. I evaluate the minimum-time task specification, which assigns a
  reward of −1 at each timestep and terminates the episode when the goal
  is reached. Under matched interaction budgets, the final policies learned
  under the minimum-time specification outperform those learned under the
  guiding-reward specifications, which provide intermediate feedback based
  on progress toward the goal. Using the minimum-time specification, four
  physical robots learn goal-reaching policies from raw-pixel observations
  within practical wall-clock budgets and without external instrumentation.
  Both the minimum-time and guiding-reward specifications were computed
  from onboard sensing. The comparison therefore isolates simplicity of speci-
  fication. The same minimum-time specification serves every task, addressing
  the third demand.

3. A streaming reinforcement learning algorithm: Action Value Gradient
  (AVG). I develop AVG, a computationally inexpensive streaming reinforce-
  ment learning algorithm. An agent using AVG updates its parameters once
  from each arriving transition and does not retain transitions for experience re-


                                      7
      play. In the survey presented in Chapter 3, I find that prior physical-robot ev-
      idence for streaming RL with neural networks was limited to a small number
      of robot implementations and environments. I evaluate agents using AVG on
      ten simulated continuous-control tasks and two physical-robot tasks with con-
      tinuous action spaces. Across repeated runs, these agents achieve competent
      performance within practical wall-clock budgets. The single-transition up-
      dates and absence of a replay buffer address the computation and experience-
      storage parts of the first demand, while the repeated-run results provide evi-

   I investigate complementary responses to limited memory and computational
resources through ReLoD and AVG. A robot using ReLoD draws on remote com-
putational resources during operation at the cost of a more complex architecture.
An agent using AVG can instead learn on-device under computation and memory
constraints by updating its parameters from individual transitions without retain-
ing them for experience replay. The minimum-time specification is computed from
onboard sensing and serves every studied goal-reaching task, addressing the third
demand. Under matched interaction budgets, the final policies learned under the
minimum-time specification outperform those learned under guiding-reward speci-
fications, although effective exploration remains necessary. Across all three contri-
butions, repeated physical-robot runs provide evidence about learning performance
and run-to-run consistency within practical wall-clock budgets.

2.2     Reinforcement Learning in the
        Context of Robotics

   The agent-environment boundary is functional rather than physical, even in
robotics, where the robot’s body suggests a physical boundary. The agent is the


                                           13
learner and decision maker, and the environment is everything else that surrounds
it. The processes governing a robot’s body, such as motor dynamics and sensing,
and even some of its internal computations, belong to the environment whenever
the agent cannot directly modify them.
   A Markov state contains the information needed to predict the distribution of the
next state and reward given an action. An observation is the information available
to the agent, such as measurements from a robot’s sensors, and need not contain the
full Markov state. In the robot experiments, St denotes this information supplied to
the agent and may therefore be noisy or incomplete. Later chapters use observation
in prose while retaining St in equations and pseudocode for notational uniformity.
If St is not a sufficient statistic of the interaction history, the MDP identities stated
in Section 2.1 do not apply exactly to it.
   Applying reinforcement learning methods to a robot task begins with specifying
the task as a Markov decision process. A human designer chooses the observations
available to the agent, the actions it can take, the reward signal, and the termination
conditions that encode the task. Each of these choices shapes what the agent can
learn and how efficiently it can learn it. Without exploitable structure, the number
of samples required to learn an effective policy grows with the dimensionality of the
state-action space, a phenomenon known as the curse of dimensionality (Bellman
1957). Specifying a reward signal that accurately captures the behavior the designer
intends is difficult (Kober et al. 2013). An agent maximizes a poorly chosen reward
as specified, through behaviors that are unsafe or that fail to capture the designer’s
intent (Amodei & Clark 2016, Booth et al. 2023).
   Robot tasks typically provide the agent with high-dimensional sensor inputs and
require continuous actions. The input may include joint positions and velocities, in-
ertial measurements, contact forces, and camera images; a single image alone may
contribute tens of thousands of dimensions. These measurements are often noisy

                                             14
and may not reveal the complete physical state because sensors have limited preci-
sion and coverage. Robot actions also commonly have several continuous dimen-
sions. Tabular representations, which maintain a separate value for each state or
state-action pair, are infeasible in such spaces.
   Reinforcement learning in high-dimensional state spaces and continuous action
spaces requires methods that generalize across states and actions. This dissertation
uses function approximation to obtain this generalization by learning parameterized
value functions and policies. Value-based methods like Q-learning (Watkins 1989)
select the action with maximum value at a given state and have proven effective
in games with discrete actions (e.g., up, down, left, right). In a continuous action
space, selecting the action with maximum value requires solving an optimization
problem at each decision. This optimization can be computationally difficult in
high-dimensional action spaces, which limits the direct application of value-based
methods to robot control. Policy-based methods instead parameterize the policy
directly, so action selection requires no maximization. They can also represent
stochastic policies, which may aid exploration (Jaakkola et al. 1994). Robot learn-
ing systems therefore often use policy gradient methods, the policy-based methods
this dissertation builds on, for continuous control (Gullapalli et al. 1994, Kober &
Peters 2008b, Kober et al. 2013, Smith et al. 2022).
   To guide the learning agent to a reasonable solution, task designers often use
task-specific domain knowledge to hand-craft a reward function with state-to-state
differences that facilitate faster learning (Matarić 1994, Booth et al. 2023); I call
these guiding rewards. In contrast, a sparse reward signal changes only at rare
events, for example, a reward of zero every timestep and +1 upon completing the
task, leaving the agent without informative feedback over long stretches. Sparse
rewards are simple to specify for a robot task, but agents may fail to learn from them
within a feasible amount of physical interaction, if exploration rarely encounters the

                                          15
rewarding events (Riedmiller et al. 2018).
   A long-lived general-purpose robot would be expected to solve a wide range
of tasks over its lifetime. Engineering a reward function for every task by hand is
cumbersome at that scale. Two properties of the reward function ease the burden.
First, rewards computed from onboard sensors alone allow the robot to evaluate
its own behavior without external instrumentation, motion capture systems, or hu-
man supervision (Hafner et al. 2021). Second, rewards that are simple to specify,
rather than requiring elaborate hand-engineering, can capture high-level goals such
as catching a ball or opening a door (Riedmiller et al. 2018), and the same specifi-
cation can extend to many tasks.


2.3     Function Approximation with Neural Networks

   Function approximation methods maintain parameterized estimates of value
functions and policies and learn the parameters from experience. The estimate
of the state-value function is written v̂(s; w), with parameters w ∈ Rd , where d
is the number of parameters, and the estimate of the action-value function is writ-
                                                                            ′
ten q̂(s, a; w). The policy is written π(a | s; θ), with parameters θ ∈ Rd , where
d′ may differ from d. This dissertation parameterizes value estimates and policies
with artificial neural networks.
   The artificial neural networks in this dissertation are feedforward networks,
fully connected or convolutional, in which each layer multiplies its input by a
weight matrix and passes each element of the result through a nonlinear func-
tion. A fully connected network with L layers computes its output by applying
hℓ = σ(Wℓ hℓ−1 + bℓ ) at each layer ℓ = 1, . . . , L, where h0 is the input, Wℓ and
bℓ are the weight matrix and bias vector of layer ℓ, and σ is a nonlinear function
applied to each element, with the final layer often omitting the nonlinearity. A con-
volutional layer takes the same form with a weight matrix that applies the same local

                                         16
filter across spatial positions (LeCun et al. 1998). The parameters of the network
are all the weight matrices and bias vectors, which constitute w when the network
represents a value function and θ when it represents a policy. Learning adjusts these
parameters with gradients of a scalar objective, taken with respect to every weight
and bias. The gradient is computed by applying the chain rule repeatedly, layer by
layer, a procedure known as backpropagation (Rumelhart et al. 1986).
   Linear function approximation, a common alternative, represents value func-
tions and policies as linear combinations of fixed features constructed by meth-
ods such as tile coding (Sutton & Barto 2018, Chapter 9) or radial basis functions
(Geramifard et al. 2013). Linear methods are computationally cheap, but their per-
formance depends on the choice of fixed features, which often requires task-specific
design. They are generally unsuitable for raw high-dimensional inputs such as im-
ages unless paired with an effective feature representation. Neural networks instead
learn feature representations from data, which reduces the need for task-specific
feature design and enables them to process high-dimensional inputs.
   The parameters of a value estimate are learned from experience by temporal-
difference (TD) learning (Sutton 1988a). After each transition, the one-step TD
update moves the estimate at the current state toward a target formed from the ob-
served reward and the estimate at the next state:


                       δt = Rt+1 + γv̂(St+1 ; w) − v̂(St ; w),

                       w ← w + α δt ∇w v̂(St ; w),


where α > 0 is a step size and δt is the TD error. When v̂ is a neural network,
∇w v̂(St ; w) is computed by backpropagation. The target is treated as fixed during
the update; the gradient therefore is taken only through v̂(St ; w), making this a
semi-gradient method (Sutton & Barto 2018). Learning the policy parameters θ

requires the policy gradient, which Sections 2.4 through 2.6 develop.
   I use the term deep reinforcement learning to refer to RL methods that represent
the policy or value function with artificial neural networks of one or more hidden
layers and adjust the network parameters by stochastic gradient methods, with gra-
dients computed by backpropagation.

Actor-Critic Methods

Actor-critic methods learn two components: a policy, called the actor, and a value
function, called the critic. The actor selects actions, and the critic estimates state
values. The temporal-difference error, computed from the critic’s estimates, evalu-
ates the action after each transition and updates the actor. REINFORCE, in contrast,
must wait until an episode ends to compute the return. Barto and colleagues intro-
duced an early actor-critic architecture for adaptive control (Barto et al. 1983).
   The simplest actor-critic method is one-step actor-critic (Sutton & Barto 2018).
                                               21
It uses Rt+1 + γv̂(St+1 ; w) as a one-step estimate of the action value and subtracts
v̂(St ; w) to form the temporal-difference error. The temporal-difference error is an
estimate of the advantage: it is unbiased when v̂ = vπθ , and with an imperfect critic
it is biased but has lower variance than the estimate based on the sampled return.
Eligibility traces extend actor-critic methods beyond one-step updates: a trace is a
short-term memory vector that accumulates recent gradients and decays them by
γλ per timestep. AC(λ) maintains one trace for the actor and one for the critic and
updates each parameter vector in proportion to the temporal-difference error times
its trace (Sutton & Barto 2018).
   This dissertation modifies the one-step actor-critic of Sutton and Barto in two
ways for use in the experiments. The first modification omits the factor γ t that
weights the actor update in an unbiased estimator of the discounted start-state policy
gradient. The omission is common in practical implementations of one-step actor-
critic (Pilarski et al. 2011, Degris et al. 2012a, Vasan & Pilarski 2017). The
factor scales the update at timestep t by γ t , which leaves little learning from states
visited late in an episode, and omitting it works better in practice. The resulting
actor update is not generally an unbiased estimator of ∇θ J(θ) for the discounted
start-state objective (Nota & Thomas 2020). I nevertheless use this practical update
throughout the experiments. The updates are

   The reparameterization gradient estimator, also known as the pathwise gradient
estimator, offers an alternative to the likelihood ratio estimator for the same target
from Equation 2.4, ∇θ EX∼pθ [f (X)] (Kingma & Welling 2014, Rezende et al. 2014,

                    X ∼ pθ        ⇐⇒           X = gθ (Z), Z ∼ h,                (2.5)

same distribution. The familiar case is the Gaussian: a sample X ∼ N (µθ , σθ2 ) can
be written as X = µθ + σθ Z with Z ∼ N (0, 1). The randomness lives in Z, which
does not involve θ, and the sample is a differentiable function of θ.
   Let f be a differentiable real-valued function. Then,


  ∇θ EX∼pθ [f (X)] = ∇θ EZ∼h [f (gθ (Z))]        ▷ change of variables, X = gθ (Z)

ratio estimator (Fan et al. 2015, Mohamed et al. 2020). The estimator requires f to
be differentiable; the likelihood ratio estimator does not.

Origins of differentiation through the critic.     Policy improvement by differen-
tiating a learned action-value estimate with respect to the action goes back to the
adaptive critic designs of the neural-network control literature (Werbos 1990). In
those designs, a critic network estimates the value, and an policy network that se-
lects the action is adjusted along the derivative of that estimate with respect to
the action. The designs were later organized into a family, including an action-
dependent variant whose critic takes the action as input (Prokhorov & Wunsch
1997). The same derivative-based policy improvement appears within approximate
dynamic programming (Powell et al. 2004). The deterministic policy gradient theo-
rem (Theorem 2) gave the idea its exact form for deterministic policies. Combined
with a replay buffer and target networks, it produced Deep Deterministic Policy
Gradient (DDPG, Lillicrap et al. 2016) and Twin Delayed Deep Deterministic Pol-
icy Gradient (TD3, Fujimoto et al. 2018), described later in this section.


Origins of policy reparameterization. Reparameterization of the policy extends
the same pathwise differentiation to stochastic policies and appears in the stochas-
tic value gradient methods (Heess et al. 2015). SVG(0), the model-free member
of the family, writes a Gaussian action as a function of noise and differentiates a
learned action-value function through it, learning off-policy from a replay buffer in
the manner of DDPG. Soft Actor-Critic (SAC) differentiates a learned action-value
function through a reparameterized action in the same way, with an entropy term
added (Haarnoja et al. 2018a). Neither work states a theorem for what the result-
ing gradient estimates. Both SVG and SAC use the estimator without a theorem
stating what it estimates. Theorem 3 was supplied later with the discounted state
                                         29
distribution made explicit, but no algorithm that follows it was proposed (Lan et
al. 2022). Chapter 6 introduces Action Value Gradient (AVG), the first practical
algorithm built on Theorem 3; it updates from each transition as it arrives, without
storing any transition.


Twin Delayed Deep Deterministic Policy Gradient

Twin Delayed Deep Deterministic Policy Gradient (TD3) is an off-policy actor-
critic method (Fujimoto et al. 2018); it serves as a baseline in the experiments
of Chapter 6. An off-policy method learns about one policy from data generated
by another and can therefore reuse experience collected by earlier versions of the
policy. TD3 stores each transition in a replay buffer and updates on minibatches
drawn from it. It learns a deterministic policy by following the deterministic policy
gradient (Thm. 2, Silver et al. 2014) and explores by adding noise to the selected
actions. The design extends Deep Deterministic Policy Gradient (DDPG), an earlier
method that pairs the deterministic policy gradient with a replay buffer and target
networks (Lillicrap et al. 2016).
   When the critic is learned with bootstrapped targets and the policy is adjusted
toward the actions with the highest estimates, estimation errors become system-
atic overestimation (van Hasselt 2010). TD3 counters the overestimation with three
mechanisms. First, two critics are learned in parallel, and the bootstrap target is
formed from the smaller of their two estimates. Taking the minimum reduces the
propagation of a positive estimation error from either critic, although it can intro-
duce underestimation. Second, small clipped noise is added to the action in the
target, so that sharp peaks in the estimate at single actions are not copied into the
targets. The two mechanisms combine in the shared critic target: on a minibatch B

In this dissertation, streaming and batch reinforcement learning denote update
regimes rather than data-collection settings. The interaction process is the same
in both regimes: at every timestep, the agent receives a state, selects an action,
transitions to a new state, and receives a reward, yielding one transition, the tuple
of state, action, reward, and next state. In streaming reinforcement learning, the
agent performs one parameter update from each transition and then discards it (Fig-

                                         36
ure 2.2a). In batch reinforcement learning, the agent stores transitions and computes
parameter updates from minibatches of stored experience (Figure 2.2b). Streaming
methods are also called incremental methods in the literature; this dissertation uses
streaming throughout. Batch reinforcement learning in this sense is distinct from
offline reinforcement learning, in which the agent learns from a fixed dataset and
collects no further experience. Every agent in this dissertation continues to collect
experience during learning.
   Streaming methods are attractive for real-time learning on physical robots be-
cause they require little memory and interleave one parameter update with each
environment transition. When the agent learns and acts in the same thread, the in-
terval between actions bounds the computation available for each update. If the
update fits within this interval, the agent can update on one transition and discard
it before selecting the next action. Deep RL methods commonly use minibatch
rather than streaming updates because updating a neural network from individual,
temporally correlated transitions can destabilize learning. Consecutive transitions
are temporally correlated, which can increase the variance of gradient estimates and
destabilize stochastic optimization. Streaming deep RL methods often learn slowly,
plateau at poor solutions, or diverge outright (Riedmiller 2005a, Mnih et al. 2015).
   Deep RL relies on batch updates and large replay buffers for its strong results
in challenging domains such as games (Mnih et al. 2015) and robotics (Ibarz et
al. 2021, Haarnoja et al. 2018a). Experience replay stores each transition in a
replay buffer and reuses it across many updates rather than discarding it after one
use (Lin 1992). Sampling each minibatch uniformly at random from the buffer
decorrelates the training samples and approximately satisfies the i.i.d. assumption.
Averaging updates over minibatches also lowers their variance and makes learning
more stable (Riedmiller 2012, Goodfellow et al. 2016). The regime borrows the
training practice of the fixed-dataset setting: the buffer stands in for the dataset. An

                                          37
early demonstration was neural fitted Q-iteration (NFQ; Riedmiller 2005a), which
recast value learning as supervised training on stored transitions and learned reliably
from reasonably few interactions.
   The stability of batch methods comes at a cost in memory and computation.
Storing transitions occupies memory, and each update sweeps a minibatch rather
than a single sample. Figure 2.3 categorizes the policy gradient methods of this
chapter by update regime, streaming or batch, and by policy gradient estimator,
likelihood ratio or reparameterization.

Chapter 3

Real-Time Reinforcement Learning
with Physical Robots

   Real-time reinforcement learning is a setting in which a learning agent runs, not
a new problem formulation. The setting has three defining facets: (a) the environ-
ment continues to evolve while the agent computes, making elapsed computation
time also elapsed environment time; (b) actions are due at target intervals, imposing
a deadline on the computations that produce each action; and (c) the agent contin-
ues learning from runtime experience rather than executing only a fixed-parameter
policy. The action cycle time is the prescribed wall-clock period between consec-
utive action deadlines. The reinforcement learning formalism neither enforces nor
prohibits these facets.
   This chapter surveys real-time reinforcement learning on physical robots. Work
that relaxes any facet falls outside the chapter’s scope: a simulator that pauses while
the agent computes relaxes the first facet, a task without action deadlines relaxes
the second, and a train-then-deploy approach that executes only a fixed-parameter
policy relaxes the third. Warm-starting an agent with pretrained weights remains
within scope if learning continues during operation.
   The three facets make the placement of computation a design decision with a
cost. Every operation between an observation and its action adds delay the agent
cannot recover. A learning update placed before action selection delays the action

                                          39
by the duration of the update. A learning update placed on a separate thread does not
delay the action, and the agent then selects actions using parameters that lag those
held by the learner. Every real-time learning system on a robot resolves the tradeoff
somehow, and the resolution has always been constrained by what the available
hardware could compute within one action cycle.
   Choosing the action cycle time is a consequential part of task design because
the cycle bounds available computation. It should reflect the timescale of the con-
trolled dynamics, the operating rates of the sensors and actuators, and the available
computational resources. A shorter cycle permits more frequent actions but leaves
less time for computation, whereas a longer cycle provides more computation time
but reduces responsiveness.
   Across three decades of prior work, the learning update moved further from
the thread that selects actions as learning methods became more computationally
expensive. Early methods updated one sample at a time inside that thread because
a linear update finished well within the action cycle time. Neural networks were
unstable when updated one sample at a time. The later methods therefore stored
past transitions in a buffer and averaged each update over a minibatch drawn from
it. An update averaged over a minibatch took longer than the action cycle time.
The update therefore moved out of the thread, first between episodes, then into a
separate thread, and finally onto a remote workstation serving one robot or many.
   I organize the survey along three axes: policy/value function class (tabular, lin-
ear, instance-based, or neural network), update regime (streaming or batch), and
update scheduling (synchronous, asynchronous, or inter-episode). The taxonomy
separates the form and update regime of the policy or value function from when
and where updates run. To compare computational cost, I estimate floating-point
operations (FLOPs) per update and plot the estimates chronologically for the sur-
veyed methods where estimation was possible (Fig. 3.3).

   The contrast between an agent-synchronized simulation and the concurrent
computations of a physical robot shows where delay enters a learning task. An
agent-synchronized simulator pauses while the agent computes (e.g., MuJoCo
[Todorov et al. 2012]), whereas wall-clock-synchronized (e.g., Physical Atari
[Javed et al. 2026]) and free-running simulators continue independently of the
agent, at a real-time rate and a compute-dependent rate, respectively. At each
timestep, an agent-synchronized simulator applies the current action, advances its
clock, and returns the new sensorimotor reading. The agent then constructs its
observation and reward, optionally updates its parameters, and selects the next
action (Fig. 3.1). Each operation completes before the next begins.
   The sensors, actuators, and environment of a physical robot operate concur-
rently and often at different rates. A sensor reading describes the environment at
the time of measurement. Communication and processing create observation-to-
action latency, during which the measurement becomes increasingly stale. Process-
                                        41
ing pipelines such as those used for image-based control can extend this latency
beyond one action cycle. Waiting for a newer observation does not eliminate la-
tency because the environment continues to evolve while the agent waits. By con-
trast, latency introduced by placing a learning update before action selection can be
reduced by issuing the action first and deferring the update (Travnik et al. 2018).

   Two approaches compensate for remaining observation-to-action latency: aug-
menting the observations with recent actions (Katsikopoulos & Engelbrecht 2003,
Ramstedt & Pal 2019) and constructing an internal agent state from a model (Walsh
et al. 2009). Mahmood and colleagues instead examined the avoidable latency in-
troduced by the organization of a physical learning task and reordered its computa-
tional stages to reduce that latency (Mahmood et al. 2018a). The task computations
divide across two concurrent processes, one for robot communication and one for
the learning agent, which exchange sensorimotor packets and actuation commands
(Fig. 3.2). Sensor and actuator threads within the communication process run at the
rates of their devices. Within the learning process, an environment thread constructs
observations and rewards, while an agent thread selects actions by their deadlines.
The resulting latency depends on where each operation runs and in what order.

It provides sensorimotor interfaces and communication through TCP and shared
memory, while allowing the experimenter to assign computations to processes and
specify the order of those computations. The shared structure supports reproducible
experiments across robot platforms while leaving the learning algorithm and place-
ment of its updates to the experimenter. The scheduling axis of the survey classifies
prior work by the latter choice (Table 3.1). The robot experiments in this disserta-

rollouts, datasets, replay minibatches, stored examples, or minibatches of model-
generated transitions. I classify methods with instance-based functions as batch
because the function itself retains experience, and its updates draw on experience
beyond the current transition. Instance-based functions appear only in the batch

   Real-time reinforcement learning on physical robots dates back more than three
decades. Early examples include a mobile robot that learned component behaviors
for box pushing and a ball-and-beam system that learned to keep the ball away
from either end of the beam (Mahadevan & Connell 1991, Benbrahim et al. 1992).
Both agents updated their parameters on the robot once per timestep, demonstrating
that streaming updates are feasible on physical hardware. Updating every timestep
requires an update cheap enough to finish before the next action is due, a constraint
both agents met with the modest computers of the period.
   Streaming RL methods with linear function approximation were applied across
a range of robot platforms and tasks. Mobile robot navigation and behavior learning
formed the largest subset (Dorigo & Colombetti 1994, Matarić 1994, Asada et al.
1996, Matarić 1997, Kelly & Keating 1998, Willgoss & Iqbal 1999). Locomotion
work spanned quadruped gaits (Kimura et al. 2001), bipedal walking (Benbrahim
& Franklin 1997, Tedrake et al. 2004, Tedrake et al. 2005, Endo et al. 2008),
standing up (Morimoto & Doya 2001), and crawling (Tokic et al. 2009, Nemec et
al. 2010). A smaller subset tackled manipulation and grasping (Huber & Grupen
1997, Fagg et al. 1998, Platt et al. 2006). In a separate body of work, agents learned
many predictions in parallel with TD learning and tile coding, and control policies
alongside them in some cases (Sutton et al. 2011, Modayil et al. 2014, Edwards et
al. 2014, Sherstan et al. 2015, Günther et al. 2016). Adaptive prosthetic control

                                         44
formed a distinct application area, where the agent learned from a human feedback
(Pilarski et al. 2011, Pilarski et al. 2013, Mathewson & Pilarski 2017, Vasan &
Pilarski 2017, Vasan 2017, Vasan & Pilarski 2018).
   A central limitation of streaming methods with linear function approximation
was their dependence on designer-specified features. A linear function can rep-
resent only the relationships encoded by those features, and constructing expres-
sive features becomes difficult as observations and actions grow in dimensionality
(Kober et al. 2013). Some work on multi-joint robots reduced the action space
faced by each policy by assigning a separate policy to each joint (Degris et al.
2012a, Vasan & Pilarski 2017). Neural networks address the representation prob-
lem differently by learning internal features from data rather than relying entirely
on features supplied by the designer.
   Early work applied streaming RL with neural networks to physical robots for
peg-in-hole insertion (Gullapalli et al. 1994), mobile robot navigation (Thrun 1995,
Millán 1996, Touzet 1997, Hailu & Sommer 1998, Gaskett et al. 2000), and bipedal
walking (Geng et al. 2005). A single-transition update does not average varia-
tion across samples in the way that a minibatch update does. Single-transition up-
dates challenge neural networks in particular because an update can change both
the network’s predictions and its learned internal representation, thereby changing
the features on which subsequent updates depend. Linear approximation with fixed
features does not undergo this representation drift, although linear methods are not
necessarily stable in every setting. Later work in the survey largely favored batch
updates and experience replay for learning with neural networks. The Action Value
Gradient algorithm developed in this dissertation revisits streaming RL with neural
networks and learns stably on physical robots (Vasan et al. 2024b).

transitions from it for additional updates (Sutton 1991). Experience replay reuses

learning updates, and computational pipelines tailored to the platform.

learning (Fidelman & Stone 2004, Kohl & Stone 2004, Kwok & Fox 2004). A
larger body of work parameterized policies as Dynamic Movement Primitives, a
trajectory representation with tunable weights (Ijspeert et al. 2002), and learned
those weights with policy-gradient or path-integral methods (Kober et al. 2008a,

Riedmiller developed the pattern into Neural Fitted Q-iteration, a general method
that collects transitions during an episode and refits the Q-function to the stored
data between episodes (Riedmiller 2005b, Riedmiller et al. 2007, Riedmiller et al.
2009). Later variants learned representations with autoencoders (Lange et al. 2012)
and combined model-based trajectory optimization with policy learning (Chebotar
et al. 2017). In the surveyed robot implementations, on-policy actor-critic meth-
ods such as trust region policy optimization (TRPO; Schulman et al. 2015) and
proximal policy optimization (PPO) follow a related schedule: they collect rollouts
while the robot acts and update their policy and value functions between episodes
(Mahmood et al. 2018a, Mahmood et al. 2018b, Korenkevych et al. 2019, Che,
Vasan & Mahmood 2023).
   Asynchronous batch RL with neural networks runs policy or value updates con-
currently with robot behavior in a separate thread or process, typically using transi-
tions stored in a replay buffer. One line of work used a central learner that received
experience from multiple robots and returned updated policies to them (Gu et al.
2017, Yahya et al. 2017, Kalashnikov et al. 2018). Another paired a single robot
with a workstation-class learner to acquire continuous-control policies on manip-
ulators (Riedmiller et al. 2018, Schwab et al. 2019, Hertweck et al. 2020) and
legged robots (Haarnoja et al. 2019, Yang et al. 2019, Ha et al. 2020, Hafner et al.
2021, Smith et al. 2022, Smith et al. 2023, Smith et al. 2024). In some of these
systems, the robot selected actions onboard and synchronized policy parameters
with the remote learner only between episodes, even though learning ran concur-

                                         49
rently. A third line extended asynchronous learning to control from image obser-
vations, using model-free methods (Bloesch et al. 2022, Yuan & Mahmood 2022)
and model-based methods that learned a forward model alongside the policy (Wu
et al. 2023). Two contributions of this dissertation belong to this category: ReLoD
partitions computation between a robot and a remote workstation for vision-based
control (Wang, Vasan & Mahmood 2023), and the minimum-time reward study uses
an asynchronous learner for goal-reaching tasks (Vasan et al. 2024a).



3.3     Discussion

Among the systems for which per-update computation could be estimated, batch
methods with neural networks grew substantially more expensive over time
(Fig. 3.3). Their estimated costs exceed those of streaming linear methods by
as much as ten orders of magnitude, whereas streaming linear methods remain
within a few orders of magnitude of their 1990s costs. The growth in per-update
cost coincides with increasingly capable CPUs, GPUs, and distributed clusters,
as well as the broader increase in computing capacity associated with Moore’s
law (Moore 1965). The estimates measure computation per update, however, not
update frequency, total training computation, runtime, or whether an update meets
a particular action deadline.
   Although computing capacity has doubled roughly every two years in accor-
dance with Moore’s law, on-device real-time learning remains rare among the sur-
veyed systems. Each hardware era in Figure 3.3 brought methods that used the
capacity of that era, so that the newest methods remained beyond the onboard com-
puters of their day.

the update out of the agent thread and allow it to use more computation, but they
may require stored experience, concurrent execution, or communication with an
external learner. This dissertation responds to the scheduling pattern in two ways.
   The first response accepts the computational demands of batch deep RL and
asks how its computations should be divided between the robot and remote hard-
ware. The asynchronous systems in the survey use different, platform-specific di-
visions, but each paper generally evaluates only one division between local and
remote computation. Within the physical-robot literature surveyed here, I did not
find a systematic comparison of what should run on the robot, what should run
remotely, and how the two should communicate. Chapter 4 presents the Remote-
Local Distributed (ReLoD) framework, which distributes action computation and
learning updates between a robot’s resource-limited onboard computer and a re-
mote workstation while preserving real-time operation.
   The second response retains the streaming update regime and addresses the in-
stability that limited its use with neural networks. In Figure 3.3, single-transition
updates remain far less expensive than the largest batch updates with neural net-
works. For a fixed-size parametric method that does not replay experience or
expand a stored representation, memory and per-update computation also remain
constant as the interaction history grows. Chapter 6 presents Action Value Gradi-
ent (AVG), a streaming actor-critic algorithm that updates from each new transition
without a replay buffer, auxiliary learning threads, or planning. In the simulated and
physical-robot experiments reported in that chapter, AVG remains stable in settings
where the standard streaming methods I evaluated diverge or fail.
   The two responses make different tradeoffs. ReLoD retains batch deep-RL algo-
rithms by allocating computation between the robot and remote hardware; configu-
rations that place learning remotely therefore depend on a reliable connection and

                                         52
sufficient remote capacity. AVG instead reduces memory and computation by elim-
inating replay and batch updates, enabling on-device real-time learning in the set-
tings evaluated in this dissertation. A method that learns within onboard resources
removes the dependence on external infrastructure altogether: a robot could learn
wherever it operates, for as long as it operates, and the memory and computation
that replay and batch updates would have consumed become available for learning
other skills and knowledge. The minimum-time reward study uses an asynchronous
learner but addresses reward design rather than the allocation or reduction of learn-
ing computation, and is therefore separate from these two responses.

Chapter 4

Real-Time Reinforcement Learning
for Vision-Based Robotics Utilizing
Local and Remote Computers

   Modern deep reinforcement learning methods rely on abundant computation,
which limits their use on physical robots. For decades, computing hardware im-
proved at the exponential pace described by Moore’s law (Moore 1965), and RL
methods grew to consume the resulting computation, a trend documented in Chap-
ter 3 (Fig. 3.3). Virtual agents, such as those playing computer games, benefited
from the increased computation because their environments are simulated: a simu-
lator can run on the same hardware as the learner, be replicated across machines to
generate experience in parallel, and be sped up beyond real time (Nair et al. 2015).
Real-time learning on physical robots cannot exploit the increased computation as
easily. The environment is the physical world, which cannot be replicated or accel-
erated. The robot therefore learns from a single stream of experience that arrives
in real time. Computation is constrained as well: a mobile robot must carry its
computer onboard, and the weight, size, and power that a robot can spare limit that
computer to a small, power-efficient device.
   One remedy pairs two computers during learning: a resource-limited local com-
puter, carried by or tethered to the robot, and a powerful remote computer connected
wirelessly. The Perseverance Mars rover is an extreme instance of the setup. The
                                        54
rover operates under stringent limits on onboard computation and storage (Verma
et al. 2023), and its remote computers, workstations on Earth, sit behind a slow,
intermittent, low-bandwidth connection. The setup trades resources against delay:
a computation placed on the local computer contends with limited resources, and a
computation placed on the remote computer incurs wireless communication delays.
Deciding which computations run on the rover and which run on Earth is therefore
a central design concern. Prior systems distributed computations between the two
computers in platform-specific ways, and each paper evaluated only one division
between local and remote computation (Haarnoja et al. 2019, Bloesch et al. 2022).
Within the physical-robot literature surveyed in Chapter 3, I did not find a system-
atic comparison of what should run on the robot, what should run remotely, and
how the two should communicate.
   I introduce Remote-Local Distributed (ReLoD), a real-time RL framework for
vision-based control that supports systematic study of how to distribute learning
computations between local and remote computers. ReLoD is a computational
framework: an integrated collection of software components that runs on the two
computers together and executes a real-time RL method on a physical robot, span-
ning sensing, action computation, learning updates, and inter-computer communi-
cation. The framework, a learning method, particular computers, and a particular
robot together instantiate a real-time learning system. Deep RL methods involve
three computationally expensive operations: action computation, policy and value
function updates, and minibatch sampling. ReLoD runs each operation as a sepa-
rate process on either computer. In each comparison, the learning method, the task,
the robot, and the computers stay fixed, and I vary only where the processes run.
Varying one thing at a time makes the comparison systematic and distinguishes
the framework from any single system built with it. The robot experiments use
SenseAct, which orders the computations of a learning task across concurrent pro-

                                        55
cesses but does not prescribe where the agent’s computations run (Mahmood et al.
2018a); ReLoD distributes them between the two computers.
   The experiments use two deep RL methods with contrasting computational pro-
files: Proximal Policy Optimization (PPO; Schulman et al. 2017) and Soft Actor-
Critic (SAC; Haarnoja et al. 2018a). An agent using PPO stores the rollouts of a
few recent episodes, updates its policy and value functions from the stored rollouts
between episodes, and then discards them. An agent using SAC stores transitions
in a large replay buffer and updates its policy and value functions from minibatches
drawn from the buffer, in a process that runs concurrently with action computation.
In the update scheduling terms of Chapter 3, the updates of an agent using PPO are
inter-episode and the updates of an agent using SAC are asynchronous. The rate at
which the robot generates experience bounds the updates of PPO, because each up-
date consumes only the newly collected on-policy data. The replay buffer of SAC,
by contrast, retains old experience for off-policy reuse, and additional computation
therefore yields more updates from the same stream. The bound and the schedule
together make PPO a control: additional computation cannot increase its updates,
and its inter-episode updates run when no action computations occur. Moving the
updates between computers therefore cannot change the actions taken within an
episode. Any benefit of a remote computer to learning updates should therefore
appear for SAC and not for PPO.
   Using ReLoD, I investigate three questions in sequence. First, given ample
computation, which agent attains higher return in real time, and does the advan-
tage persist under limited computation? The SAC agent attained more than twice
the return of the PPO agent within the same wall-clock time, and on the weakest
computer its return fell below that of the PPO agent. Second, can distributing ac-
tion computation and learning updates between the two computers recover the lost
return? The SAC agent, computing actions on the local computer and updating

                                        56
on the remote computer, recovered most of the lost return, whereas the PPO agent
attained similar returns in every mode. Third, how far does the recovery extend?
An onboard computer too limited to sustain the learning updates of the SAC agent
supported real-time learning when paired with a remote workstation. I study these
questions on two vision-based tasks, one with a UR5 robotic arm and the other with
an iRobot Create2 mobile robot.

4.7     Conclusion

Together, the three experiments show that a robot limited to an edge computer
learned in real time with SAC when the learning updates ran on a remote work-
station, and that moving computation to a remote computer raises return only for
an agent that performs more updates when given more computation. Section 4.4
showed that the SAC agent, given ample computation, attained more than twice
                                         69
the return of the PPO agent within the same wall-clock time, and that on the em-
ulated Jetson Nano its return fell below that of the PPO agent on the workstation.
Section 4.5 showed that in the Remote-Local mode the SAC agent attained nearly
the return it attained on the workstation, because its replay buffer converts added
computation into more updates from the same stream of experience, while the PPO
agent attained similar returns in every mode. Section 4.6 showed real-time learning
with SAC on a mobile robot whose onboard computer cannot run the learning up-
dates alone. The comparison of modes also shows that a real-time learning system
is sensitive to where delays occur: in the Remote-Only mode, WiFi latency delayed
every action the robot took, whereas in the Remote-Local mode the same latency
only postponed learning updates.
   I introduced ReLoD, an open-source framework that distributes the computa-
tions of a real-time RL agent between a local and a remote computer, and used it
to answer the three questions this chapter posed: on limited computers the SAC
agent lost its advantage over the PPO agent, in the Remote-Local mode it attained
nearly its workstation return, and a Jetson Nano paired with a remote workstation
ran real-time learning with SAC on a mobile robot.



4.8     Limitations and Future Work

The experiments in this chapter cover a narrow range of tasks, methods, and hard-
ware. Each comparison used a single task per robot and five independent runs.
The results therefore establish orderings rather than precise magnitudes. I studied
only two methods, chosen for their contrasting computational profiles and update
schedules; an agent using another off-policy method may benefit differently from
remote computation. I attributed the low return of the SAC agent in the Remote-
Only mode to the variable latency of transmitting actions over WiFi; the results


                                        70
on Create-Reacher are consistent with the attribution, but the experiments did not
vary the latency or measure its effect on the timing of actions. The Remote-Local
mode also requires a reliable wireless connection to a nearby workstation, which a
laboratory provides but a robot deployed outside one may lack.
   Future extensions of ReLoD should support more learning methods. Model-
based RL reopens the question of where each computation should run, because
decision-time planning performs heavy computation on the action pathway rather
than the update pathway. In my experiments, the policy networks were small
enough that the agent computed each action within the action cycle time; a larger
policy network would require different design choices, such as computing every ac-
tion from proprioceptive input while a slower concurrent process refreshes a cached
image representation.
   Future extensions should also revisit the division of computation itself, which
was fixed by hand in every configuration. An agent could instead learn to allo-
cate its own computation and memory, deciding when to compute locally, when to
defer to the remote computer, and how much experience to retain, in the spirit of
metareasoning (Russell & Wefald 1991, Hay et al. 2012) and adaptive recurrent
computation (Graves 2016).
   A truly autonomous robot cannot depend on a remote computer at all, because it
may operate where no connection to one exists or lose the connection during oper-
ation. Chapter 6 develops a computationally inexpensive streaming reinforcement
learning algorithm whose updates run on the onboard computer alone, without the
remote computation that the Remote-Local mode requires.

Chapter 5

Minimum-Time Task Specification
for Goal-Reaching Reinforcement
Learning

   A robot expected to solve many tasks over its lifetime cannot rely on a human
to supply task-specific knowledge for each one in advance. It is often easier to
recognize that a task is solved, that the mug is picked up or the door is opened,
than to specify the movements required to solve it. A reward crafted by hand for
each task ties each new skill to a designer who holds task-specific knowledge, and
the dependence limits how many tasks the robot can acquire on its own. A reward
specification built from a test for success alone narrows the designer’s burden to the
easier judgment: recognizing that the task is solved.
   Many real-world robot learning problems, such as pick-and-place or arriving
at a destination, amount to reaching a goal state as soon as possible. Formulated
as episodic reinforcement learning tasks, goal-reaching problems admit a specifi-
cation that matches the designer’s intent: a reward of −1 on every timestep, with
termination upon reaching the goal state. I call it the minimum-time specification
because maximizing the undiscounted sum of the rewards minimizes the time taken
to reach the goal. The reward encodes nothing about how to reach the goal and
therefore does not bias the solution toward a designer’s guess at good behavior.
The minimum-time specification is often overlooked in favor of guiding rewards
                                         72
(also known as dense rewards), which provide an informative learning signal on
most timesteps, typically by scoring progress toward the goal, and are perceived
as easier to learn from. Guiding rewards can bias the solutions the agent finds and
lead to suboptimal outcomes because they reflect the designer’s preferred behavior
(Riedmiller et al. 2018, Booth et al. 2023, Knox et al. 2023).
   I contrast the minimum-time specification with two alternatives, a guiding-
reward and a contact-reward specification, on goal-reaching tasks in simulation,
and with the guiding-reward specification on physical robots. In simulation, poli-
cies trained under the minimum-time specification reached the goal two to three
times faster than policies trained under guiding rewards, remained on target longer,
and matched or surpassed them on the guiding-reward objective itself. The num-
ber of times the initial policy reached the goal within a fixed budget of timesteps
predicted how quickly and consistently learning succeeded. Guided by a target-
hit threshold, agents using SAC learned pixel-based policies from scratch on four
physical robot platforms, with a constant negative reward on every timestep, within
a few hours of experience. On the two robot arms, minimum-time policies again
reached the goal faster, although marginally, and remained on target longer.


5.1     Related Work

The community has met the difficulty of learning without an informative per-
timestep reward signal in two ways: (a) make the reward more informative through
guiding and shaping terms, crafted by hand or generated automatically; and (b)
keep the reward sparse while strengthening exploration. Sutton and Barto advise
that the reward signal communicate to the agent what the designer wants achieved
rather than detail how to achieve it, and the minimum-time specification follows
the advice (Sutton & Barto 2018). The specification requires only a test for success
and leaves the objective unambiguous. The chapter therefore asks when learning

                                        73
under it succeeds, a question complementary to many exploration strategies.


Reward Design Task designers commonly craft reward functions through trial
and error so that agents both learn quickly and perform the task well (Lee et al.
2019, Wu et al. 2021, Knox et al. 2023). Designers often augment a reward that sig-
nals task success with guiding or shaping terms that steer the agent toward a desired
policy. The resulting reward function both communicates the performance metric
and prescribes how to improve it. An early instance rewarded steps up a progress
gradient rather than goal attainment alone (Matarić 1994). A shaping term pre-
serves the optimal policy when it is potential-based, taking the form γΦ(s′ ) − Φ(s)
for a potential function Φ over states (Ng et al. 1999). A guiding term need not be
potential-based, and ad hoc shaping is widely recognized as unsafe because it may
alter the optimal solution of the task (Amodei & Clark 2016, Knox et al. 2023).
Designers who iterate by trial and error also risk overfitting the reward function
to the algorithm they used while designing it (Booth et al. 2023, Muslimani et
al. 2025). One approach automates the design, searching over candidate reward
functions with a large language model that uses task-specific prompts, reward tem-
plates, and evolutionary search (Ma et al. 2024). Searching over reward functions,
like searching over neural architectures, costs substantial computation. Other ap-
proaches derive reward signals from pre-trained vision-language models, avoiding
the search, but the feedback from such models can be too imprecise for tasks that
require fine spatial distinctions (Rocamonde et al. 2024, Wang et al. 2024). Each
route to a more informative reward exacts a cost: designer effort and bias risk when
crafted, computation or imprecision when automated.


Exploration Strategies for Learning with Sparse Rewards An agent learning
from sparse rewards may take many actions before it encounters a state where the
reward differs. Exploration therefore determines whether learning begins at all.
                                         74
One remedy has the agent learn auxiliary tasks alongside the target task. An agent
using SAC-X learns policies for a set of auxiliary tasks and schedules them to ex-
plore the observation space in search of the sparse rewards of externally defined
target tasks (Riedmiller et al. 2018). A later extension defined the auxiliary tasks
internally, on raw sensor streams alone, and agents using it solved tasks as complex
as Ball-in-Cup from scratch (Hertweck et al. 2020). The remedy carries a cost:
someone must define the auxiliary tasks, and the agent must learn and schedule
them alongside the target task. Goal relabeling offers another route to learning from
sparse rewards. Hindsight Experience Replay (HER) enables an agent to learn from
failed episodes by treating previously seen states as pseudo-goals (Andrychowicz et
al. 2017). HER applies only to environments where every reachable state can serve
as a goal state and therefore does not help when the task specifies one goal state or
a small set. HER also does not extend directly to vision-based tasks, where distinct
visual features characterize the goal states. An extension of HER to vision-based
reaching and pushing on a 7-degree-of-freedom (DOF) Sawyer arm relies on a fixed
arena with an overhead camera that always views the target, and it still requires ev-
ery reachable state on a 2D plane to be a valid goal (Nair et al. 2018). This chapter
proposes no new exploration strategy. Instead, the chapter offers an inexpensive
predictor of whether an agent can learn a minimum-time task quickly and reliably:
the number of target hits under the initial policy.


Learning from Pixels from Scratch on Physical Robots With DayDreamer, a
model-based method, four physical robots learned real-world tasks under a single
system (Wu et al. 2023). Visual Foresight (Ebert et al. 2018) combines a learned
video prediction model with online planning, but it suits only short-horizon tasks
and must generate images during planning, at substantial computational cost. Both
approaches require a model. In the robot experiments of this chapter, agents instead


                                          75
learn pixel-based control in real time with a model-free algorithm.


Minimum-Time Tasks Minimum-time problems in optimal control ask for the
control that transfers a system from an initial state to a final state in the shortest
time (LaSalle 1959, Kahn & Roth 1971, Bobrow et al. 1985, Shin & McKay 1985,
Chapter 9 of Chui & Chen 2012). One approach combines classical path planning
with model-free deep RL to train a neural network policy for flying a quadrotor
through a sequence of waypoints, among obstacles, in minimum time (Penicka et
al. 2022). Control benchmarks in RL, such as Mountain Car (Moore 1991) and
DotReacher (Garg et al. 2022), also use a reward of −1 on each timestep until
termination, matching the minimum-time specification. The specification induces
an exact ordering: the return of an episode is the negative of the time the agent takes
to reach the goal. Expected returns therefore rank policies precisely by expected
time to goal, with the time-optimal policies at the top. A guiding term replaces the
ranking with a proxy, and an agent that climbs the proxy can converge to a local
optimum of it, a behavior that collects the guiding signal without solving the task.

an episode: when the agent exceeds it, the environment moves the arm to a dif-

self through a pre-programmed routine. A timeout accordingly incurs a penalty
of −K, where K is the number of timesteps the reset requires. Consider a task
with a time limit of 100 timesteps and a reset penalty of −20. If the agent times
out three times and then reaches the goal in 25 timesteps, the episode has return
−100 − 20 − 100 − 20 − 100 − 20 − 25 = −385 and length 385. Learning curves
in this chapter report undiscounted returns computed in this manner.
   The contact reward and minimum-time specifications are closely related. The
contact reward gives a positive reward upon success and zero everywhere else, a
form often called a sparse reward because a differentiating reward signal arrives
only rarely. The minimum-time reward is an extreme form of sparse reward: the
reward never changes, and the differentiating signal arrives only through the return,
the accumulated reward of an episode. The minimum-time specification is also
simpler, because preferring to reach the goal sooner requires no discounting.

    Target hits of a random initial policy offer an inexpensive guide. A target hit
occurs each time the agent satisfies the success test, and target hits therefore count
how often the agent reaches a goal state. I recorded target hits for an initial Gaussian
policy N (0, 1) over 20K timesteps across a range of time limits, on Reacher and
on a minimum-time variant of Ball-in-Cup (Tassa et al. 2018). Target hits varied
substantially with the time limit on all three tasks (Fig. 5.5), and no single time limit
was best across tasks. The tuning is therefore per task.
                                                            84
   Target hits under the initial policy may also predict whether learning will suc-
ceed, because learning cannot begin in earnest until the agent has reached a goal
state at least once. I tested the connection between target hits and learning success
on four tasks: Non-Visual and Visual Ball-in-Cup, Non-Visual Reacher-Easy, and
Non-Visual Reacher-Hard. The learning curves tracked the target-hit counts closely
(Fig. 5.6): time limits that produced many target hits under the initial policy yielded
fast, consistent learning, and time limits that produced few target hits yielded slow
or failed learning. A learning system can accordingly choose the time limit of a
minimum-time task by measuring target hits under the initial policy across candi-
date limits and selecting a limit that yields many hits.


5.5     Learning Vision-Based Minimum-Time Tasks on
        Physical Robots

   I test whether an agent can learn a minimum-time task on a physical robot from
raw pixels, from scratch, within a practical wall-clock budget. Four vision-based
robot tasks provide the test (Fig. 5.8, Fig. 5.9). On the physical robots, episodes
terminate according to the most recent image, and termination is therefore defined
on the observation rather than on an underlying state. I chose the time limit for
each task by the recipe of Section 5.4, requiring the initial policy to exceed 10
target hits within 20K timesteps, with one exception: the 750-timestep limit on
Franka-VisualReacher fell below the threshold and was retained as a test of learning
under insufficient target hits. Robot control typically runs at 10–125 Hz. Collecting
20K timesteps therefore takes at most 35 minutes, a feasible cost for real-world
experimentation. Training then proceeded with an asynchronous implementation
of SAC (Yuan & Mahmood 2022), using the hyperparameters in Appendix A.3 and
a reward of −1 on every timestep until the episode ends.
   Create-Reacher. The task follows an existing minimum-time task (Wang,

                                          85
Vasan & Mahmood 2023). A Depstech 4K camera and a Jetson Nano 4GB com-
puter support image-based observations and onboard inference (Fig. 5.8a). The
objective is to reach one of the green sticky notes swiftly. The episode terminates
when a green sticky note occupies at least 20% of the most recent image.
   UR5-VisualReacher. The task is a minimum-time adaptation of an existing
guiding-reward task (Yuan & Mahmood 2022). The objective is to move the fin-
gertip of the arm to a red target on the screen as fast as possible (Fig. 5.8b). The
episode terminates when the target occupies more than 1.5% of the most recent im-
age. The target remains unchanged until the arm reaches it. Upon termination, the
arm resets to a predefined posture and a new random target appears.
   Vector-ChargerDetector. The task is a new vision-based goal-reaching task on
Anki Vector, a low-cost mobile robot (Fig. 5.9a). The agent sends velocity com-
mands to the wheels every 100 ms over WiFi. The episode terminates when the
charger symbol is centered and occupies roughly 25% of the most recent image.
During a reset, Vector moves backward and reorients itself in a random direction.
   Franka-VisualReacher. The task is a new task on the Franka Emika Panda, a
7-DOF robot arm. The objective is to move the wrist-mounted camera close to a
bean bag on the table (Fig. 5.9b). The agent sends velocity commands for each joint
at 25 Hz. Each episode places the arm and the bean bag in random positions. The
episode terminates when the bean bag occupies more than 12% of the most recent
image.
   A practical demand of real-time learning is that the reward be computable where
the robot learns. Robot learning experiments often compute rewards from external
instrumentation, such as motion capture systems, that is available in the laboratory
but not during deployment (Kober et al. 2013, Ibarz et al. 2021). Rewards computed
from the robot’s onboard sensing free the robot from that infrastructure (Hafner et
al. 2021). Every reward in the physical-robot experiments, minimum-time and

5.7                   Conclusion

The minimum-time specification defines a goal-reaching task with nothing more
than a reward of −1 on every timestep and termination upon reaching a goal state,

                                                                             91
narrowing task specification to recognizing success. On Reacher in simulation,
policies trained under the minimum-time specification reached the goal two to three
times faster than policies trained under guiding rewards, remained on target longer,
and matched or surpassed them on the guiding-reward objective itself. The choice
of time limit substantially affected how often the initial policy reached a goal state.
The time limit is therefore better treated as a tunable solution parameter than as a
fixed property of the problem. The number of target hits under the initial policy
predicted how quickly and consistently learning succeeded across time limits in
simulation, providing an inexpensive measurement to take before committing to
a full training run. Guided by a target-hit threshold, agents using SAC learned
pixel-based policies from scratch on four physical robot platforms within a few
hours of experience, and learning was slower and less consistent under the one time
limit that fell below the threshold. On the two robot arms, minimum-time policies
again reached the goal marginally faster and remained on target longer than guiding-
reward policies.


5.8     Limitations and Future Work

The central comparison in this chapter spans one family of tasks. Every task is a
goal-reaching problem, and the claim that the minimum-time specification produces
better final policies than guiding rewards rests on reaching variants in simulation
and on robot arms. Whether the advantage holds on tasks with richer objectives,
such as locomotion at speed or dexterous manipulation, is untested, and the claim
should be read as scoped to goal reaching until then.
   The comparison between the specifications also deserves a more even account-
ing of tradeoffs. The minimum-time specification assumes a reliable way to recog-
nize success, and constructing one is not always free: each robot task in this chapter
defines success through a hand-chosen threshold on the most recent image, whereas

                                          92
the simulation tasks terminate on the simulator state. Some design effort therefore
relocates from the reward to the termination condition. For tasks where success is
easy to recognize but progress is hard to score, such as the goal-reaching tasks stud-
ied here, the minimum-time specification is the natural choice. For tasks where a
meaningful progress measure is readily available and success is ambiguous, a guid-
ing reward may be both easier to specify and faster to learn from. A systematic
characterization of which task properties favor each specification remains open.
    The target-hit measurement requires the initial policy to reach a goal state oc-
casionally. On hard exploration problems where the initial policy never succeeds
within a feasible budget, the measurement correctly forecasts failure but offers no
remedy. Exploration strategies for sparse rewards, surveyed in Section 5.1, are
complementary here: they aim to produce the early successes that the measurement
requires. Curriculum learning (Narvekar et al. 2020) is also complementary: a
sequence of tasks of increasing difficulty, each specified in minimum-time form,
could carry the agent to competence on tasks where the initial policy never reaches
a goal state.
    The threshold of 10 target hits per 20K timesteps is a heuristic calibrated to one
set of hyperparameters, and all results use a single algorithm, SAC. Whether the
threshold transfers across algorithms, replay ratios, and batch sizes remains open.
    The evaluation measures learning speed and final performance but not adapta-
tion. The chapter motivates the minimum-time specification by competent perfor-
mance within a practical budget and, beyond it, by continual adaptation. It evaluates
the specification by learning curves within a fixed budget and by the policies those
budgets produce, neither of which includes a change in the task. Whether a policy
learned under the minimum-time specification adapts faster than one learned under
a guiding reward when the goal or the dynamics change remains untested.

Deep Policy Gradient Methods
Without Batch Updates, Target
Networks, or Replay Buffers

   Learning directly on a physical robot constrains the memory and computation
available to a reinforcement learning agent. Deep RL methods stabilize learning
through mechanisms such as replay buffers, batch updates, and target networks,
and each mechanism carries a memory or computation cost that can exceed the
budget of an onboard computer. The ReLoD framework of Chapter 4 accommo-
dates these costs by distributing computation to a remote workstation, at the price
of a more complicated setup and a dependence on wireless connectivity. Learning
with only onboard resources removes that dependence but requires an algorithm
that forgoes the expensive stabilizing mechanisms. Streaming learning, in which
the agent updates from each transition (an observation, action, reward and next ob-
servation) as it arrives and then discards it, eliminates the memory and computation
costs of those mechanisms entirely. Agents trained with prior methods and deep
neural networks, however, fail catastrophically in the streaming setting.
   With the Action Value Gradient (AVG) algorithm, an agent learns stably in the
streaming setting without replay buffers, batch updates, or target networks. An
agent using AVG computes an entropy-regularized reparameterization policy gra-
dient from the most recent transition and stabilizes its updates with observation
                                         94
normalization, penultimate normalization, and TD-error normalization. AVG is
the first algorithm to follow the reparameterization policy gradient theorem (The-
orem 3) in the streaming setting: its actor update is the theorem’s single-sample
estimate, taken from the on-policy stream, and the contribution of the chapter is
making that update stable without batch mechanisms. In AVG, the three techniques
together fill the stabilizing role that replay buffers, batch updates, and target net-
works serve in batch deep RL methods.
   Experiments on simulated benchmarks and two physical robots established the
effectiveness of AVG. On Gymnasium and DeepMind Control Suite tasks, agents
trained with AVG matched the final performance of agents trained with SAC and
a one-million-transition replay buffer on several tasks and surpassed them on the
Dog tasks, whereas agents trained with the streaming baselines failed catastroph-
ically. On a UR5 arm and an iRobot Create 2, agents learned control policies in
roughly two hours of experience, with all computation for the mobile robot run-
ning onboard an edge device. In the survey presented in Chapter 3, I find that prior
physical-robot evidence for streaming deep RL was limited to a small number of
robot implementations and environments; the experiments of this chapter demon-
strate stable streaming deep RL across a breadth of settings that the surveyed work
does not reach.

Before the first episode has been completed, the agent uses σδ = 1. TD-error nor-
malization controls changes in error magnitude across tasks and stages of learning.
It depends only on sampled rewards, transition discounts, and cumulative rewards,
rather than on the internal parameters of the actor or critic, and requires constant

   Normalizing the TD error rather than the reward keeps the task unchanged.
Scaling the reward by a fixed positive constant leaves the optimal policy unchanged,
but shifting it does not, since a constant added to every timestep changes the value
of ending an episode sooner. Reward normalization as used in PPO also estimates
its scale online, and the reward and the return change with the estimate. Dividing
the TD error by σδ instead leaves the reward and the return as the task defines them.


Connection between TD-error normalization and step-size adaptation. The
TD error enters the critic update only as a scalar factor, and dividing it by σδ is
therefore equivalent to dividing the critic’s step size by σδ ; the actor update contains
no TD error and is unaffected. TD-error normalization is a step-size normalization
for the critic, one scalar shared by all its parameters, with the scale taken from the
returns rather than from the gradient. It leaves the critic’s fixed point unchanged,
since a positive scaling of the update does not move its zero, and it is applied before
Adam, which then rescales each parameter’s update by a running estimate of that
parameter’s gradient magnitude.
   Adam does not make the normalization redundant, because Adam has no access
                                          101
to the scale of the targets. It normalizes each parameter’s update by that parameter’s
gradient history, averaged over roughly the last thousand updates; when the return
scale changes, as it did on Humanoid-v4 from tens to thousands, the history lags
the change. A single large TD error then adds its squared gradient to the running
average, which decays slowly. Every update that follows is divided by the inflated
square root of that average, so the steps shrink for hundreds of updates until the av-
erage settles. TD-error normalization divides by a scale estimated from the returns
themselves, and the update therefore tracks the target scale as it changes; it applies
the same scalar to every critic parameter, which preserves the gradient’s direction
and bounds only its magnitude before Adam rescales the update.


Convergence guarantees.       The convergence properties of AVG are known only
for a simplified variant. The paper introducing AVG (Vasan et al. 2024b) analyzes
a variant that keeps the reparameterization gradient and the single-transition up-
date but drops entropy regularization and normalization, and assumes a linear critic
and independent samples. Under those conditions the policy gradient converges to
a neighborhood of zero set by the critic’s approximation error, a stationary-point
result rather than convergence to q∗ . No result covers AVG as implemented, or
any deep actor-critic method, including SAC and TD3; the stability of AVG is an
empirical finding, and Section 6.4 examines the mechanisms behind it.

6.3      AVG on Simulated Benchmark Tasks

Agents trained with AVG learned effectively across a suite of simulated benchmark
tasks on which agents trained with prior streaming methods failed catastrophically.
The comparison included OAC, a prior streaming method; agents using OAC with
linear function approximation have learned in real time on simulated and physical-
robot tasks (Degris et al. 2012a, Vasan & Pilarski 2017, Vasan & Pilarski 2018).
The comparison also included streaming adaptations of SAC and TD3, which, like
AVG, build on reparameterization policy gradients. To adapt SAC and TD3 to the
streaming setting, the minibatch and replay buffer sizes were set to 1, so that ex-
perience was processed one transition at a time; these variants are referred to as
SAC-1 and TD3-1, where the suffix denotes both the replay buffer capacity and the
minibatch size. Section 2.6 describes both methods, Algorithm 1 and Algorithm 3
give the OAC and SAC pseudocode respectively, and Appendix A.5 lists the hyper-
parameter values.
   The hyperparameters of each method were optimized by random search, which
is more efficient than grid search in high-dimensional search spaces (Bergstra
& Bengio 2012).     For each method, 300 hyperparameter configurations were
evaluated; for each configuration, agents were trained with ten random seeds
for 2M timesteps on five continuous-control environments: Ant-v4, Hopper-v4,
HalfCheetah-v4, Humanoid-v4, and Walker2d-v4. Each configuration was ranked
by its average undiscounted return per run, and the top configuration for each en-
vironment was then used to train agents for 10M timesteps with 30 random seeds.
Appendix A.5 describes hyperparameter selection for the DeepMind Control Suite
tasks.

6.4     Stabilizing Streaming Policy Gradient Methods

Agents using AVG learn stably where agents using unnormalized streaming meth-
ods fail, and the stability traces to the three normalization techniques. Without nor-
malization, gradient norms exploded and learning failed; with all three techniques,
agents achieved the best performance among the eight possible combinations. Ap-
plying the same techniques to other streaming methods recovered the performance
of agents trained with OAC but not of agents trained with SAC-1 or TD3-1, and
adding a target critic to AVG did not improve performance.


Instability Without Normalization

Instability in deep RL often manifests as high variance (Bjorck et al. 2022), reduced
expressivity of the network over time (Nikishin et al. 2022, Sokar et al. 2023), or
a gradual drop in performance (Dohare et al. 2024, Elsayed & Mahmood 2024,
Elsayed et al. 2024), attributed largely to the non-stationarity of the data stream.
Large regression target scales were identified as another common source of learning
difficulty (Lyle et al. 2024). In the training runs of this chapter on Humanoid-v4, for
instance, bootstrapped targets ranged from −20 to 8000. The critic must therefore
represent values that fluctuate widely across stages of training, which can produce
excessively large TD errors and destabilize learning.
   Agents trained with AVG without any normalization, a variant denoted AVG− ,
failed on Humanoid-v4 with exploding gradient norms (Figure 6.3). The figure
compares these agents with agents trained with SAC, which learned successfully.
In SAC, batch updates smooth noisy gradients, and target critics stabilize the boot-
strap targets; AVG− includes neither mechanism. The gradient norms of the agents
trained with AVG− grew excessively large, particularly in the critic network. The

                          The figure invites two explanations, offered here as hypotheses consistent with
the diagnostics rather than as demonstrated causes. The critic’s gradient norm grew
far larger than the actor’s, by about nine orders of magnitude at its peak. The
critic’s gradient, δ∇w q̂, is proportional to the TD error, which can be as large as the
bootstrapped target when the estimate is far off. The actor’s gradient, ∇θ gθ ∇a q̂,
contains no TD error and is multiplied by the derivative of the tanh squashing, which
vanishes as the actions saturate. A critic that bootstraps on its own inflated estimates
                                                                   109
can push its weights in a consistent direction at every update; Adam bounds the size
of each parameter’s step, not the parameters or the values, and consistently directed
bounded steps still grow the weights, with the gradient norm growing alongside.
SAC’s batch updates, twin critics, and target critic each interrupt that growth.
   The diagnostic comparison suggests that stable learning in AVG requires bal-
ancing update magnitudes across timesteps and episodes, reducing the influence
of outlier experiences. Normalizing the inputs, the penultimate features, and the
TD errors partly balances these magnitudes. Appropriately normalizing observa-
tions improves performance (Andrychowicz et al. 2021), likely because it improves
learning dynamics (Sutton 1988b, Schraudolph 2002, LeCun et al. 2002). Normal-
izing hidden-layer activations serves a similar role inside the network: layer nor-
malization (Ba et al. 2016) bounds the scale of the features, and recent work finds
that it stabilizes value learning in deep RL (Ball et al. 2023, Lyle et al. 2023). Nor-
malizing both the targets (e.g., by normalizing the rewards, Engstrom et al. 2019)
and the observations is a well-established strategy in widely used algorithms such
as PPO, improving performance and stability (Rao et al. 2020, Huang et al. 2022).


Disentangling the Effects of Normalization

Agents trained with the combination of all three techniques consistently achieved
good performance: observation normalization maintains good learning dynamics
(norm obs in the figures), penultimate normalization reduces instability and im-
proves plasticity (pnorm, Bjorck et al. 2022), and TD-error normalization resolves
the problem of large bootstrapped target scales (norm td, Schaul et al. 2021).
   Welford’s procedure was selected for observation normalization because it
maintains statistics over the entire data stream; recency-weighted estimates did
not perform well in preliminary experiments. Penultimate normalization improves
plasticity in a manner similar to layer normalization (Lyle et al. 2023), and agents

6.6     Conclusion

Streaming policy gradient methods are viable for deep RL and require less mem-
ory and computation than batch methods, an advantage for onboard robotic appli-
cations. With the Action Value Gradient algorithm, an agent learns stably in the
streaming setting, and agents trained with AVG outperformed agents trained with
prior streaming methods and resource-constrained batch methods on the simulated
benchmarks and physical-robot tasks of this chapter. Normalization of the obser-
vations, the penultimate features, and the TD errors enables agents using AVG to
learn stably even on high-dimensional control problems, filling the role that replay
buffers, batch updates, and target networks serve in batch deep RL methods. The
experiments on a robotic manipulator and a mobile robot extend the physical-robot
evidence for streaming deep RL, which the survey in Chapter 3 finds limited to a
small number of robot implementations and environments. AVG makes deep RL
feasible within the limited onboard resources of robots, a step toward continual
adaptation and long-term robot autonomy.

6.7     Limitations and Future Work

The main limitation of AVG is low sample efficiency: agents trained with AVG
require more experience than agents trained with off-policy batch methods such as
SAC. The performance of agents trained with AVG is also sensitive to the choice
of hyperparameters; a valuable extension would reduce this sensitivity so that a
single configuration performs well across environments. The formulation is limited
to continuous action spaces but could be extended to discrete action spaces with
the Gumbel-Softmax technique (Jang et al. 2017). The AVG update also omits the
factor γ t in the actor update, as the one-step actor-critic (Algorithm 1) does; the
omission is common in practice and biases the update, and an existing correction
addresses it (Che, Vasan & Mahmood 2023).
   Low sample efficiency and hyperparameter sensitivity both follow from the
single-transition update. Without a minibatch to average the gradient or a target net-
work to steady the bootstrap target, each update carries the variance of one sample;
the step size must therefore be tuned to the task, and more experience is needed to
reach a given performance. Figure 6.2 compares agents trained with AVG for 10M
timesteps with agents trained with SAC for 1M. Even at that ratio of timesteps, the
agents trained with SAC used far more computation and memory: SAC updated
from a minibatch of 256 at every timestep (Table A.4) and held a replay buffer
of 1M transitions, about 256M transitions processed over 1M timesteps, whereas
AVG processed one transition per update and held none, 10M transitions over 10M
timesteps, roughly 25 times fewer. On a physical robot, experience costs more than
computation, and the trade favors AVG only where batch methods cannot run, as on
the two robot tasks of Section 6.5. Where a workstation is reachable, the distributed
setup of Chapter 4 keeps the sample efficiency of batch methods.




                                         119
Relation to Stream-X.      Concurrent with the publication of AVG, the Stream-X
class of methods stabilized streaming deep RL for prediction and control with meth-
ods such as TD(λ), AC(λ), and Q(λ) (Elsayed, Vasan & Mahmood 2024). The two
lines of work differ in the methods they cover and the means they use. Both nor-
malize inputs and features. Stream-X adds reward normalization, eligibility traces
(Chapter 12 of Sutton & Barto 2018), sparse initialization, and an optimizer that
bounds the step size to prevent overshooting, and it was applied to likelihood ra-
tio and action-value methods. AVG instead normalizes the TD errors and is the
first streaming method built on the reparameterization policy gradient, the fam-
ily to which SAC and TD3 belong. Nothing prevents the techniques of Stream-X
from being applied to reparameterization methods; no streaming reparameteriza-
tion method existed to apply them to before AVG. Neither work compares against
the other because the two appeared at the same time. A comparison under matched
conditions remains to be done, and replacing Adam with the bounded step-size op-
timizer (i.e., ObGD) of Stream-X may improve the robustness of AVG.


Second-order optimization. Natural policy gradient and other second-order
methods have improved policy gradient learning with batch updates (Kakade 2001,
Peters & Schaal 2008, Schulman et al. 2015), but they suit the streaming setting
poorly. A second-order method needs an estimate of the curvature, the Fisher
information matrix or the Hessian, and a single transition supplies only a rank-one
sample of it. A usable estimate requires a batch of transitions or statistics accumu-
lated over many timesteps, which lose accuracy as the policy changes. Storing and
inverting even a block-diagonal approximation of the curvature (Martens & Grosse
2015) costs memory and computation that grow with parameter count, beyond
the per-update budget of an onboard computer. One practical route is a curvature
estimate updated from each transition, such as a running diagonal or Kronecker-


                                        120
factored Fisher. For the actor, the compatible-features form of the natural gradient
is another: incremental natural actor-critic algorithms obtain it at no extra cost
with linear function approximation (Bhatnagar et al. 2007). Extending that form to
neural networks and to the reparameterization gradient is an open problem.


Eligibility traces. The one-step update generalizes to a weighted average of n-
step updates through eligibility traces, with λ setting the weights (Singh & Sutton
1996, van Hasselt et al. 2021); traces improved learning in the Stream-X class of
methods, but they do not extend to AVG directly. The critic can use them as in
Sarsa(λ), because its update is a temporal-difference update on action values. The
actor cannot: a likelihood ratio actor, such as the actor in OAC, accumulates a trace
of ∇θ log π and multiplies the trace by the TD error, so that one error assigns credit
to several past actions. The actor’s update in AVG, ∇θ q̂(S, Aθ ; w), contains no
TD error. The critic’s action gradient at the current state carries all the information
the actor receives, and there is nothing for a trace to multiply. Multi-step credit can
therefore reach the actor only through a critic trained toward λ-returns, and whether
that indirect route recovers the gains traces gave Stream-X is left for future work.


Off-policy learning.    AVG is on-policy, and an off-policy variant is a natural next
step. Both updates use the transition the current policy just generated, and the
critic bootstraps on an action sampled from the current policy, so no importance-
sampling ratio appears in either. An off-policy variant would let the agent learn
about many policies from one stream of experience. It would also let a safer or more
exploratory policy control the robot while the agent learns about a target policy,
and it would let the agent learn from demonstrations and stored experience, the pre-
training direction of Chapter 7. Such a variant must correct the state distribution
of both updates, because the states would be distributed according to the behavior
policy. Off-policy actor-critic leaves the mismatch uncorrected for the actor (Degris
                                         121
et al. 2012b); for the critic, the mismatch combined with bootstrapping and function
approximation can cause divergence (Chapter 11 of Sutton & Barto 2018). Multi-
step targets would in addition carry per-decision importance-sampling ratios, whose
variance grows with the backup length unless truncated as in Retrace (Munos et al.
2016) or V-trace (Espeholt et al. 2018).


Learned models and shared representations. Two extensions could improve the
sample efficiency of streaming methods such as AVG. An agent that learns auxiliary
tasks over a shared representation gains an additional source of training signal from
the same stream. A model-based RL agent learns a model of the environment and
updates its policy and value function from simulated transitions as well as real ones,
so that each real transition contributes to learning both directly and through the
model (Sutton 1991). A model-based agent built on AVG, in the manner of Dyna,
would learn the model, the critic, and the actor from the same stream and update
the actor and critic from simulated transitions between real ones.


Continuing tasks and continual learning.          A continuing task has no episode
boundaries; in continual learning, the task or the environment changes over time.
The actor and critic updates of AVG suit both: they use one transition at a time,
need no episode boundary, and keep memory and computation constant as experi-
ence accumulates. For a continuing task, the TD-error scaling would replace the
return of the completed episode (Algorithm 6) with a running estimate, and the
average-reward objective, with differential values, could replace the discounted one
(Wan et al. 2021). For continual learning, the normalization statistics accumulate
over the entire stream by Welford’s procedure and would track a change in dynam-
ics, observations, or rewards slowly; recency-weighted estimates, which performed
worse on the fixed tasks of this chapter, may be needed instead. Testing AVG in
either setting is left for future work; Chapter 7 discusses continual learning further.

Chapter 7

Conclusions and Future Work


7.1     Contributions

Robots that operate in the real world over long periods encounter conditions that
their designers cannot anticipate. The prevailing practice in robot learning trains
a policy before deployment and holds it fixed afterward, which leaves a deployed
robot unable to update its behavior from experience collected after deployment.
Real-time reinforcement learning removes the separation between training and de-
ployment: the robot learns from its runtime experience. The dissertation set out
to advance real-time RL on physical robots by addressing three practical demands:
meeting action-cycle, computation, and memory constraints; reaching competent
performance reliably within a practical wall-clock budget; and using rewards com-
putable onboard and simple to specify across tasks. It makes three contributions
toward that objective.
   Computationally intensive RL methods require more computation and memory
than most robots carry onboard. ReLoD addresses that constraint by supplementing
the robot’s onboard computer with a remote workstation (Chapter 4). Experiments
showed that the performance of an agent using Soft Actor-Critic degraded as on-


                                       123
board computational resources were reduced, and that a robot using ReLoD recov-
ered performance by drawing on remote computational resources during operation.
With ReLoD, vision-based control policies were learned from scratch on physi-
cal robots within a few hours, including on a mobile robot carrying only an edge
computing device. When a remote workstation is available, the choice of learning
method is no longer bound by the robot’s onboard computer alone.
   The minimum-time specification assigns a constant reward of −1 at each
timestep and terminates the episode when the goal is reached. Under matched in-
teraction budgets, final policies learned under the minimum-time task specification
outperformed those learned under guiding-reward specifications on goal-reaching
tasks (Chapter 5). The comparison covered four physical robots learning from
raw-pixel observations without external instrumentation. Under the minimum-time
specification, the burden of task specification shifts from reward design to explo-
ration. For the goal-reaching tasks studied, one simple specification, computed
from onboard sensing, served every task.
   The Action Value Gradient algorithm demonstrates that an agent can learn sta-
bly with streaming policy gradient updates to deep neural networks (Chapter 6).
An agent using AVG updates its parameters once from each arriving transition and
retains no experience for replay. It therefore requires less memory and less compu-
tation per update than batch methods. Agents using AVG outperformed agents us-
ing existing streaming methods and resource-constrained batch methods across ten
simulated continuous-control tasks. Normalization of the observations, the penulti-
mate features, and the temporal-difference errors enabled agents using AVG to learn
stably even on high-dimensional control problems, and may serve a stabilizing role
analogous to replay buffers, batch updates, and target networks in batch deep RL
methods. The experiments on a robotic manipulator and a mobile robot extend the
physical-robot evidence for streaming deep RL, which the survey in Chapter 3 finds

                                       124
limited to a small number of robot implementations and environments. An agent
using AVG can learn on-device under computation and memory constraints, a step
toward continual learning and adaptation in the real world.
   The three contributions can compose into a single approach. ReLoD and AVG
cover opposite ends of the computational spectrum: ReLoD applies when the robot
can reach a remote workstation, and AVG runs within the robot’s onboard resources
alone. Faster hardware will not merge the two ends: each hardware era in the survey
brought methods that used the capacity of that era (Chapter 3), and the tasks that
robots are expected to take on will demand more computation than the tasks solved
in this dissertation. The gap between onboard and remote computation is likely
to persist, and different deployment scenarios will continue to call for different
solutions, whether fully on-device real-time learning or a distributed setup such as
ReLoD. The minimum-time specification is independent of the learning method and
pairs with either. For a goal-reaching task, a practitioner can therefore distribute the
learning when remote computation is available, stream the updates on-device when
it is not, and in both cases specify the task with a constant reward of −1 terminated
at the goal. The dissertation evaluates each contribution separately; demonstrating
the full composition on a single robot system remains for future work.
   Each contribution suits a different case. ReLoD suits a robot that can maintain
a connection to a workstation and a task that calls for a batch method, as the vision-
based tasks of Chapter 4 did. AVG suits a robot that must learn on its own onboard
computer. Examples include a rover beyond the reach of any workstation and a fleet
with more robots than workstations to serve them. AVG also suits any deployment
in which the computation and memory that streaming updates save can be spent on
other work. The minimum-time specification suits any goal-reaching task in which
the robot can detect the goal from its own sensing and the initial policy reaches
it often enough, as it did in the tasks of Chapter 5; when the initial policy never

                                          125
reaches the goal, a guiding reward or a curriculum of easier goals is needed first.
   The contributions also serve long-term autonomy. A robot that operates au-
tonomously for months or years must learn continually, acquiring new capabilities
without discarding old ones as its world changes. Alternating phases of opera-
tion and retraining could supply adaptation, but the robot would respond to change
only at the next retraining. Learning in real time removes the lag: the robot adapts
as it operates. The empirical studies in the dissertation evaluated learning within
bounded experimental runs, not adaptation across sequences of environmental or
task changes. Reliable real-time learning is necessary, but not sufficient, for con-
tinual adaptation, and the dissertation provides evidence for it on physical robots, a
step toward robots that learn throughout their operational lifetimes.



7.2     Directions for Future Work

Real-time reinforcement learning on physical robots remains an early-stage tech-
nology. I consider three directions that extend the contributions: combining pre-
training with real-time RL, streaming model-based RL, and continual learning for
long-term autonomy.

Combining Pre-Training with Real-Time Learning

A real-time learner can start from pre-trained parameters rather than from scratch.
All experiments with physical robots in this dissertation involved learning from
scratch, which required hours of robot interaction for each task. Learning from
demonstrations and sim-to-real transfer avoid training on the robot by pre-training
a policy that is deployed without further training, but the policy can degrade in
situations that the demonstrations or the simulator did not cover, and correcting
failures through further training is expensive and slow (Wagenmaker et al. 2024).


                                         126
Pre-training and real-time learning are complementary: pre-training provides com-
petence at deployment, and real-time learning can correct failures where they occur.
   Recent methods combine pre-training with subsequent reinforcement learning.
Reinforcement learning from prior data places offline transitions or demonstrations
in a replay buffer and updates on minibatches that mix prior and new experience
(Vecerik et al. 2017, Ball et al. 2023). Imitation-bootstrapped reinforcement learn-
ing trains a reinforcement learning policy alongside a pre-trained imitation policy
that proposes candidate actions for exploration and for the bootstrap targets (Hu et
al. 2024). Both approaches depend on replay buffers and batch updates, inheriting
the computational demands of batch deep RL, and construct the learner’s remaining
components, such as the value function, from scratch at deployment.
   Meta-learning trains an agent across a distribution of tasks so that it learns a
new task from the same distribution faster than from scratch (Thrun & Pratt 1998).
Model-agnostic meta-learning (MAML) optimizes the initial parameters for a fixed
adaptation procedure, a few gradient updates computed from batches of trajectories
on the new task (Finn et al. 2017). As used, adaptation is performed once: the
agent collects a few trajectories on the new task, updates, and then acts without
further learning. Nothing in the procedure requires learning to stop there. The PPO
agent of Chapter 4 also updates from batches of trajectories between episodes and
continues throughout operation; pairing MAML with a learner of that kind would
let the pre-trained initialization adapt in real time. The task distribution, however,
must be built in advance, in practice in simulation, and adaptation is fast only on
the variation it contains. Real-time learning is motivated by conditions no task
distribution anticipates, and how to meta-train an agent that keeps learning under
them is an open problem.
   A promising path pre-trains the agent as a whole, not the policy alone. An agent
whose value functions and other components are pre-trained alongside its policy

                                         127
need not construct them from scratch at deployment, and if it learns by streaming
updates, it need not carry a replay buffer onto the robot. Realizing that path requires
care in setup, so that every component of the pre-trained agent remains usable by
real-time learning at deployment.


Streaming Model-Based Reinforcement Learning

Model-based reinforcement learning offers a path to sample efficiency that model-
free streaming methods, as developed in this dissertation, do not exploit. A model-
based agent learns a world model, an approximation of the environment dynamics,
and uses the model to generate simulated experience for updating value functions
and policies (Sutton 1991), or to plan at decision time (Williams et al. 2017). An
agent can gain sample efficiency by performing learning updates on simulated expe-
rience in addition to real experience, while an agent using a streaming method such
as AVG updates only once per real transition. Current model-based deep RL meth-
ods rely on large replay buffers and batch updates over stored experience. Their de-
mands therefore exceed the onboard resources of most robots (Hansen et al. 2024,
Hafner et al. 2025). Streaming updates could make model-based learning feasible
on small onboard computers.
   Chapter 6 demonstrates streaming learning of the policy and the value function.
Streaming learning of a world model with neural networks remains an open prob-
lem. Extending streaming deep RL methods to model learning would yield a fully
streaming algorithm for model-based deep RL, one in which the policy, the value
function, and the world model all update from each transition as it arrives. A fully
streaming algorithm could scale its computation to the available resources, gaining
sample efficiency by generating more simulated experience as computation grows,
while storing no past experience.



                                         128
Continual Learning for Long-Term Autonomy

Long-term autonomy in a changing world requires continual learning through shifts
in the input distribution, changes in the environment dynamics, and sequences of
tasks (Thrun & Mitchell 1995). Two failure modes obstruct continual learning:
catastrophic forgetting, the degradation of performance on previously learned tasks
as a new task is learned (McCloskey & Cohen 1989), and loss of plasticity, the
declining ability of a network to learn as training proceeds (Dohare et al. 2024).
Existing continual learning methods largely assume batch data and explicit task
boundaries (Lesort et al. 2020, Powers 2023); a robot operating in the real world
provides neither.
   Onboard memory is fixed while experience accumulates without bound. A con-
tinual learner can therefore retain a subset or a summary of its experience but not
all of it. Methods whose memory and computation do not grow with experience are
suited to learning under a fixed resource budget. AVG meets that requirement: an
agent using AVG updates from each transition as it arrives and discards it, keeping
its memory and computation per timestep constant as experience accumulates. RL
agents face non-stationarity even in a single stationary task: bootstrapping shifts
the targets of the value function, and policy updates shift the data distribution. Nor-
malization enabled stable learning under these shifts (Chapter 6), and penultimate
normalization has been reported to preserve plasticity in a manner similar to layer
normalization (Lyle et al. 2023). The runs of Chapter 6 lasted 10M timesteps on
a single task and showed no loss of plasticity, but they did not test for it; a test
would run an agent through a sequence of tasks or changes in dynamics and mea-
sure whether later tasks are learned as readily as earlier ones (Dohare et al. 2024).
Whether streaming methods can mitigate catastrophic forgetting and maintain plas-
ticity over such sequences remains an open question.

A.2      Estimation of FLOPs per Learning Update

I assign each learning update a computational cost in floating-point operations
(FLOPs) using the approximation
                          ⎧
                          ⎪
                        . 6 Peff n for neural networks,
                          ⎪
                          ⎨
       FLOPs per update =
                          ⎪
                          ⎩2 Peff n for linear function approximation,
                          ⎪


where Peff is the effective parameter count of the function approximator and n is
the number of samples processed per update. The factor of six follows the standard
accounting of two FLOPs per parameter per sample for the forward pass and four
for the backward pass. The factor of two counts one multiplication and one addition
per active weight for the prediction. The gradient of a linear prediction with respect
to its weights is the feature vector itself, and computing it therefore requires no
propagation comparable to a neural network’s backward pass.
   The effective parameter count depends on the representational regime. For neu-
ral networks, Peff equals the total number of trainable parameters, computed from
the layer dimensions reported in each algorithm’s source publication or official im-
plementation. For linear function approximation with sparse features, Peff equals
the number of active features multiplied by the number of weight vectors main-
tained by the algorithm, because inactive features contribute no operations.
   The number of samples per update depends on the update regime. For batch
methods, n equals the minibatch size multiplied by the number of gradient steps per
update. Streaming methods, which update from the most recent transition alone,
have n = 1. When a paper reports multiple experiments, the estimate uses one
representative configuration, typically the primary physical-robot experiment.

A.8       The Effect of Other Network Normalization
          Techniques

Penultimate normalization, used by AVG, is one of several techniques for normal-
izing neural network features. Layer normalization normalizes the pre-activations
across the features within each layer (Ba et al. 2016). Root mean square (RMS) nor-
malization rescales the pre-activations by their root mean square without centering
their mean (Zhang & Sennrich 2019). Penultimate normalization normalizes only
the activations of the penultimate layer, immediately before the final layer (Bjorck
et al. 2022).
   Figure A.1 compares the three normalizations in AVG on Ant-v4, Hopper-v4,
and Humanoid-v4. Agents using AVG with penultimate normalization consistently
outperformed agents using AVG with layer normalization or RMS normalization.
